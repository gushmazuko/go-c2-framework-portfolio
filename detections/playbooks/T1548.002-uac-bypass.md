# T1548.002 — Abuse Elevation Control: Bypass UAC

**Range surface:** scenario SC-11 — the fodhelper/eventvwr
`ms-settings` hijack executed through the framework shell. No UAC-bypass
logic exists in the implant (scope line).

## What the range does

The operator writes the `HKCU\Software\Classes\ms-settings\Shell\Open\command`
hijack point and `DelegateExecute`, then launches `fodhelper.exe`
(auto-elevate) — the elevated process runs the hijacked command.

## What is honestly visible

- **Registry writes are fully visible** (Sysmon EID 13, the lab config
  includes the ms-settings keys): both `Shell\Open\command` and
  `DelegateExecute`.
- **EID 1**: `fodhelper.exe` (or `eventvwr.exe`) launched from the C2
  shell — a high-integrity-trigger binary with no user consent UI is
  anomalous on its own.
- The elevated child then appears with the hijacked command line,
  parent `fodhelper.exe` — parent-child breakage vs. the normal UAC
  consent flow.

## What to alert on

- **Sigma** `9e938f81-591b-4a41-bbef-a6023ff333ab`
  (2026-uac-bypass-fodhelper.yml): the ms-settings registry writes.
- Hunt: `fodhelper.exe`/`eventvwr.exe` process creates at all — on a
  normal estate these binaries are near-zero frequency.
- The elevated child's parent lineage (no consent.exe / no user
  interaction in between).

## False-positive profile

- The registry rule can see troubleshooting tools touch ms-settings;
  the `Shell\Open\command` *value-set* specifically is the high-signal
  arm. fodhelper/eventvwr execution rules are near-FP-free.

## Validation

1. In the shell (as a non-elevated admin user): run the SC-11 steps —
   reg add + `fodhelper.exe`.
2. Expect the Sigma rule on both registry events; expect EID 1 for
   fodhelper and the elevated child.
3. `whoami /groups` in the elevated child vs. the shell — the integrity
   jump without a consent dialog is the takeaway; record which detections
   fired in order.
