# T1562.001 — Impair Defenses: Disable or Modify AMSI

**Range surface:** scenario SC-06 — a public atomic (Atomic Red Team
style) executed **through the framework shell** as a documented
procedure. The implant itself never touches AMSI (scope line).

## What the range does

The operator runs the atomic steps in the interactive shell — typically
`powershell` one-liners that either flip the
`System.Management.Automation.AmsiUtils.amsiInitFailed` flag or patch
`AmsiScanBuffer` in memory.

## What is honestly visible

- **Command-line/string variants ARE visible** to Sysmon EID 1: the
  class names (`AmsiUtils`, `amsiInitFailed`) appear in the PowerShell
  command line when the atomic is delivered that way.
- **In-memory patching is NOT visible** to classic Sysmon: no file, no
  registry, no image load. EDR-only territory: hook integrity checks on
  `AmsiScanBuffer` (page-protection change, hotpatch stub overwrite),
  and ETW-TI provider telemetry for tamper events.
- Downstream effect: after successful blinding, subsequent malicious
  PowerShell that *should* trigger AMSI/Defender detections goes quiet —
  the "detection silence" anomaly is itself hunt-worthy.

## What to alert on

- **Sigma** `513c2ae7-9f96-408b-8697-99ed4b0f2d2a`
  (2026-amsi-tampering-indicators.yml): PowerShell command line
  containing `AmsiUtils` / `amsiInitFailed` / `AmsiScanBuffer`.
- Correlate with `90120763-...spawns-shell` (the C2 parent chain) — the
  atomic runs as a child of the agent's shell.
- EDR: script-block logging (EID 4104 in PowerShell operational log)
  retains decoded script content — hunt `amsiInitFailed = $true`
  assignments there too.

## False-positive profile

- Security tooling, AMSI verification scripts, and attack-simulation
  frameworks legitimately reference these strings. Parent lineage
  (agent shell) separates the range from AV test suites.

## Validation

1. `interact <session>` → `shell` → `powershell`.
2. Run the SC-06 steps (see the scenario file for the exact commands).
3. Expect the Sigma rule on the EID 1 event; with Defender live, expect
   (or deliberately observe the absence of) a real-time detection —
   both outcomes are worth recording and should be recorded in the coverage
   report.
