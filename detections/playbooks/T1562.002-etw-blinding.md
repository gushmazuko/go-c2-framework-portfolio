# T1562.002 — Impair Defenses: Disable Windows Event Logging / ETW

**Range surface:** scenario SC-07 — public atomics executed through the
framework shell. The implant itself never touches ETW (scope line).

## What the range does

The operator runs ETW-blinding steps in the shell: typically patching
`EtwEventWrite` in `ntdll`/`clr` in-memory or unregistering the
PowerShell ETW provider (`EtwEventUnregister` on the provider handle)
so script-block telemetry dries up.

## What is honestly visible

- **String variants ARE visible** to Sysmon EID 1: public atomics
  reference `EtwEventWrite`/`EtwEventUnregister` in their command lines.
- **The in-memory patch is NOT visible** to classic Sysmon. EDR/ETW-TI
  sees it: integrity of `EtwEventWrite` prologue, provider
  unregister/anomaly analytics.
- **The effect is visible in absence**: PowerShell script-block logging
  (EID 4104) and Sysmon EID 22/EID 1 flows thin out for the blinded
  process while the process keeps doing things — "activity without
  telemetry" is the detection shape.

## What to alert on

- **Sigma** `5c3ba4c2-0018-4116-8906-e97d547ec244`
  (2026-etw-tampering-indicators.yml): PowerShell command line with
  `EtwEventWrite` / `EtwEventUnregister`.
- EDR: tamper analytics on `EtwEventWrite` prologue; provider
  registration changes from user-context processes.
- SOC hunt: for a process whose Sysmon EID 1 exists, an EID
  4104-silence *while the process is active* — the blinded-process gap.

## False-positive profile

- ETW diagnostic tooling and profiling scripts reference provider names;
  parent lineage (C2 shell) is the discriminator.

## Validation

1. Baseline first: run a benign `powershell -c whoami` in the shell and
   confirm script-block logging lands (EID 4104).
2. Run the SC-07 steps; expect the Sigma rule on the EID 1 event.
3. Repeat the benign command: with blinding live, 4104 goes quiet for
   that session while the Sysmon EID 1 (process create) keeps flowing —
   that contrast IS the takeaway, record it in the coverage report.
